# 주간 프로젝트 개인 기획 및 설계 수행 보고

이번 주 프로젝트 기획 및 설계 과정에서 저는 주도적으로 아이디어를 발산하고, 기술 스택을 고려한 서비스 구체화 및 코어 기능의 상세 설계를 진행했습니다. 특히 다중 사용자 환경의 동시성 제어 로직 기획과 향후 도입할 데이터 추천 파이프라인의 초기 구상에 집중하여 이번 주 과제를 수행했습니다.

## 1. 초기 아이디어 발산 및 제안
WebRTC와 데이터 처리 기술을 실생활 서비스에 녹여내기 위해, 기술적 구현 가능성을 염두에 두고 아래 다섯 가지 기획안의 초안을 도출하고 팀 내 논의를 이끌었습니다.

* **홈카페 원격 라이브 클래스:** WebRTC 데이터 채널을 이용해 강사와 시청자 간 타이머 등 UI 상태를 0.1초 만에 동기화하는 매뉴얼 브루잉 플랫폼 기획.
* **실시간 원격 안전 점검 플랫폼:** QR코드 스캔을 통한 통제실과의 P2P 화상 연결 및 초저지연 화면 드로잉 지시 동기화 시스템 제안.
* **음성 인식 기반 설비 매뉴얼 RAG:** Python 기반 RAG 파이프라인을 구축해, 작업자의 음성을 분석하고 공정 매뉴얼에서 해결책을 찾아주는 AI 어시스턴트 구상.
* **로컬 화상 투어 서비스:** 현지인과 여행객의 화상 연결 시 지도 줌인 및 핀 설정을 실시간 동기화하는 투어 플랫폼 아이디어 제시.
* **AI 기반 쇼핑 티어 메이커:** Python 추천 알고리즘을 활용해 유사 의류를 찾고, 참여자들이 실시간 공동 보드에서 상품을 등급별로 분류하는 소셜 쇼핑 서비스 기획.

## 2. 기획 피벗 및 타겟 재설정 주도
초기 '패션 코디 추천'이라는 큰 방향성에서 출발했으나, 서비스의 당위성을 확보하기 위해 기존 방식의 한계점을 분석하고 타겟을 좁히는 기획 피벗 과정을 주도했습니다.

* **한계점 분석:** 옷장 기반 코디의 높은 진입 장벽, 설문 조사 기반 추천의 피로도, 포화 상태인 챗봇형 추천의 한계를 지적하며 방향 전환을 제안했습니다.
* **타겟 재설정:** '옷을 사야 하지만 검색은 귀찮고, 구매 직전 친구의 컨펌이 필요한 사람'으로 타겟을 구체화했습니다.
* **WebRTC 당위성 확보:** 단순한 링크 공유를 넘어, 친구들과 실시간으로 떠들며 티어표를 만드는 '쇼핑의 오락화(Gamification)'로 서비스 핵심 가치를 확립했습니다.

## 3. 최종 기획안 구체화 및 AI/데이터 파이프라인 도입 구상
최종 선정된 '쇼핑몰 링크 하나로 시작되는 패션 취향 투기장' 기획의 상세 비즈니스 흐름을 정리하고, 향후 개발에 필요한 인공지능 및 데이터 파이프라인의 **초기 구상 및 기술 스택 검토**를 진행했습니다.

* **서비스 흐름 정의:** 방장의 쇼핑몰 링크 입력 ➡️ AI의 실시간 유사 상품 배경 제거(누끼) 스티커 생성 ➡️ WebRTC 기반 실시간 티어표 배치 및 음성 소통으로 이어지는 핵심 로직을 수립했습니다.
* **추천 및 전처리 파이프라인 구상 (리서치 단계):**
    * 빠르고 가벼운 실시간 이미지 배경 제거 처리를 위해 웹 서비스 인퍼런스 속도에 적합한 모델(U^2-Net 또는 RMBG-1.4)의 활용 방안을 검토했습니다.
    * 유사 상품 추천 로직 구현을 위해 PyTorch 기반의 Feature Vector 추출(ResNet50, ViT 등)과 코사인 유사도(Cosine Similarity)를 활용하여 15~20개의 후보군을 필터링하는 데이터 처리 흐름을 초기 구상했습니다.
* **기술 차별점 도출:** WebRTC DataChannel을 통한 객체 좌표값 초저지연 동기화 방식과, 놀이 후 S/A 티어 상품을 결제로 유도하는 숨겨진 상업성(Sneaky Commerce) 모델을 기획했습니다.

## 4. 핵심 기능 명세 및 동시성 제어 알고리즘 설계 (F-05)
서비스의 코어 모듈인 '공동 티어표 편집 모듈'을 전담하여, 다중 사용자 접속 시 발생할 수 있는 동시성 문제와 충돌 제어 알고리즘을 직접 설계하고 상세 인수 조건을 작성했습니다.

* **F-05-01: 상품 카드 드래그 및 실시간 동기화**
    * 카드의 등급 및 내부 순서 저장 로직을 구상했습니다. 이동 중 DB 삭제 시 원위치 복구 및 안내를 제공하는 예외 처리 정책을 수립했습니다.
* **F-05-02: 공동 편집 및 충돌 제어 (핵심 알고리즘 설계)**
    * 서버가 이벤트 순번과 보드 버전을 중앙 통제하도록 설계했습니다.
    * **카드 충돌 로직:** 동시 이동 요청 시 서버 최초 수락 건만 반영하는 방어 로직을 작성했습니다.
    * **위치 충돌 로직 (Append 정책):** 다른 카드가 동일 순서로 동시 이동 시, 늦은 요청 카드를 다음 순서로 밀어넣는 알고리즘을 설계하여 데이터 유실을 방지했습니다.
* **F-05-03: 공동 후보 추가 및 동시성 제어**
    * 후보 20개 제한을 두고, 초과 동시 요청 발생 시 서버 단에서 요청을 즉시 튕겨내고 에러를 반환하는 동시성 제어 정책을 세웠습니다.
* **F-05-04: 최종 후보 자동 배정 및 방장 확정**
    * 티어 랭킹(S➡️B순)에 따른 3개 상품 자동 배정 알고리즘과 상위 티어 부족 시 하위 티어 교차 배정 우선순위 로직을 짰습니다. 컨펌 전 참여자 미리보기 동기화 상태를 정의했습니다.
* **F-05-05: 보드 종료 및 결과 확정 프로세스**
    * 미분류 상품의 자동 C티어 일괄 이동 로직과, 종료 즉시 모든 보드를 읽기 전용(Read-only)으로 잠금 전환하는 상태 제어 플로우를 기획했습니다.
