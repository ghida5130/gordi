# AI 이미지 모델 2차 블라인드 평가 회고

- 회고일: 2026-07-28
- 평가 데이터 기준: 2026-07-28 12:46 KST
- 평가 대상: 1차 상위 이미지 생성 모델 4개
- 평가 방식: 모델명을 숨긴 전수 A/B 비교와 품질 항목별 평가
- 데이터 범위: 목업을 제외한 2차 실제 Run
- 집계 상태: 중간 집계

## 1. 한 줄 결론

2차 중간 집계에서는 `Nano Banana 2`가 종합점수 79.6점으로 뚜렷한 선두를
기록했다. 다만 평가된 실제 Run이 5개이고 같은 케이스가 중복됐으며 D1·E2 실제
Run이 빠져 있으므로, 현재 결과는 최종 모델 확정이 아니라 다음 평가를 진행할
우선순위를 정하는 강한 중간 신호로 해석한다.

## 2. 이번 단계에서 바꾼 것

### 2.1 1차와 2차 평가를 분리했다

1차 입력·평가·대시보드는 그대로 보존하고 2차 전용 흐름을 별도로 만들었다.

- 2차 입력: `?round=2`
- 2차 통합 결과: `?round=2&dashboard=1`
- 기존 1차 데이터에 `evaluation_round`가 없는 경우 `ROUND_1`로 해석
- Run마다 평가 라운드, 프로필, 프롬프트 버전과 핏 규칙 버전을 저장

2차 프로필은 다음처럼 고정했다.

| 항목 | 값 |
| --- | --- |
| 프로필 | `round-2-fit-aware` |
| 프롬프트 | `canonical-v2-fit-aware` |
| 핏 규칙 | `relative-fit-v1` |
| 후보 수 | 4개 |
| 비교 쌍 | Run당 6개 |
| 로컬 폴백 | 사용하지 않음 |
| 생성 조건 | 4개 모델이 모두 성공해야 평가 가능 |

### 2.2 후보를 1차 상위 4개로 줄였다

2차에는 다음 네 모델만 남겼다.

1. GPT Image 2
2. Nano Banana 2 Lite
3. Nano Banana 2
4. FLUX.2 Max

7개 모델을 평가하던 1차의 Run당 비교 수는 최대 21개였지만, 2차는 4개 모델의
전수 비교인 6개로 줄었다. 평가 부담을 줄인 대신 의상 조합과 입력 조건을 더
구체적으로 검증할 수 있게 됐다.

### 2.3 사용자 입력을 MVP 범위로 줄였다

초기 2차 화면은 어깨, 가슴, 허리, 골반 등 상세 신체 치수를 직접 입력받았지만,
실제 MVP 명세에 맞춰 다음 입력만 받도록 축소했다.

- 성별
- 키
- 몸무게
- 사전제작 아바타 선택

아바타의 상세 기준 치수는 프리셋에 보관하고, 서버가 입력된 키와 몸무게에 맞춰
보정한다. 사용자가 알기 어려운 신체 치수를 직접 입력하는 부담을 없애면서도
핏 계산에는 일관된 기준을 사용할 수 있게 했다.

### 2.4 고정 핏 태그를 동적 핏 계산으로 바꿨다

1차에는 의상 하나에 `슬림핏`, `오버핏` 같은 태그를 미리 고정했다. 그러나 같은
옷이라도 사용자가 선택한 사이즈와 아바타 체형에 따라 실제 핏은 달라진다.

2차에서는 판매 페이지의 선택 사이즈 실측과 아바타 기준 치수를 서버에서
비교한다.

- 상의: 가슴 여유량, 어깨 차이, 소매 차이, 총장 비율
- 하의: 허리 여유량, 힙 여유량, 밑위, 허벅지와 밑단 비율, 총장
- 결과: `TIGHT`, `REGULAR`, `RELAXED`, `DROPPED`, `WIDE`,
  `HIGH_RISE` 같은 아바타 상대 핏 태그

프론트의 핏 태그는 입력 확인용 미리보기이고, 최종 태그와 프롬프트는 서버가
원시 치수로 다시 계산해 확정한다.

### 2.5 착용컷의 인물 오염을 프롬프트 구조로 막았다

1차에서 의상 레퍼런스에 사람이 포함되면 모델이 선택한 마네킹 대신 레퍼런스 속
인물을 결과의 기준으로 사용하는 문제가 있었다.

2차 프롬프트는 입력 이미지의 역할을 명시적으로 분리한다.

- `PERSON BASE`: 얼굴, 신체, 체형, 비율, 포즈, 카메라의 유일한 기준
- `GARMENT ONLY`: 색상, 로고, 패턴, 재질, 재단과 봉제 구조만 참고

착용컷에는 레퍼런스 인물의 얼굴·피부·머리·체형·포즈와 함께 보이는 다른 의상을
무시하라는 정책을 개별 의상마다 추가한다. 여러 입력이 충돌하면 항상
`PERSON BASE`가 우선한다.

### 2.6 무신사 기반 2차 데이터셋을 구성했다

기존 단일 의상 프리셋 6개와 상·하의 조합 프리셋 6개를 분리해 제공한다.

| 유형 | 수 | 목적 |
| --- | ---: | --- |
| 사이즈 민감도 | 4개 | 같은 이미지에서 선택 사이즈와 실측만 바뀔 때 핏 변화 확인 |
| 레퍼런스 오염 | 2개 | 같은 상품의 단독컷과 착용컷 비교 |
| 상·하의 조합 | 6개 | 실제 사용 비중이 높은 한 벌 입력 검증 |

조합 프리셋은 여성 3개와 남성 3개로 구성했다.

- 여성: 크롭 티+부츠컷, 슬림 폴로+파라슈트, 그래픽 크롭 티+와이드 슬랙스
- 남성: 로고 티+와이드 데님, 그래픽 티+파라슈트, 체크 셔츠+와이드 슬랙스

여성 하의가 없던 초기 데이터셋에는 부츠컷, 파라슈트, 와이드 슬랙스를 추가했다.
각 의상에는 원본 상품 URL, 원본 이미지 URL, 선택 사이즈 실측, 착용컷 여부와
로컬 이미지 SHA-256을 기록했다.

### 2.7 2차 결과 대시보드를 추가했다

2차 대시보드는 1차와 데이터를 섞지 않고 다음 정보를 제공한다.

- 4개 후보 종합 순위
- 선호도와 품질 평균
- 의류 보존, 체형 보존, 자연스러움, 결함 억제 점수
- Run별 참여자, 투표 수와 현재 1위
- 평가자 본인의 완료·미완료 Run
- 미완료 Run의 평가 계속하기 링크
- 2차 API 성공률, 지연시간과 기록 비용

## 4. 2차 중간 집계 결과

### 4.1 종합 순위

| 순위 | 모델 | 종합점수 | 선호도 | 품질 | 승/무/패 | 둘 다 아님 | 집계 Run | 품질 평가 수 |

현재 1위와 2위의 종합점수 차이는 23.3점이다. 1차에서 상위 3개가 근소한 차이로
붙었던 것과 달리, 실측과 상·하의 조합을 반영한 현재 2차 표본에서는
`Nano Banana 2`의 우위가 크게 나타났다.

종합점수 계산은 1차와 같은 방식을 유지한다.

```text
선호도 = (승리 + 0.5 × 무승부) ÷ 전체 비교 수 × 100
품질 환산점수 = 품질 평균 ÷ 5 × 100
종합점수 = 선호도 × 0.6 + 품질 환산점수 × 0.4
```

## 6. 잘된 점

### 6.1 1차를 보존하면서 실험 조건을 분리했다

기존 결과를 덮어쓰지 않고 라운드별 프로필과 대시보드를 분리했다. 과거 데이터와
새 프롬프트 결과를 섞지 않아 1차 대비 2차 변화를 설명할 수 있다.

### 6.2 MVP 입력과 내부 계산의 책임을 분리했다

사용자는 성별·키·몸무게와 아바타만 고르고, 서버가 상세 신체 기준과 핏 태그를
결정한다. 사용성은 단순하게 유지하면서 생성 프롬프트에는 필요한 수치를 전달할
수 있게 됐다.

### 6.3 문제를 문구가 아닌 입력 역할로 해결했다

“레퍼런스 인물을 따라 하지 말라”는 단순한 부정 문구에 그치지 않고,
`PERSON BASE`와 `GARMENT ONLY`로 이미지의 권한을 구분했다. Run 데이터에 실제
최종 프롬프트와 입력 전략도 함께 저장해 결과를 재현할 수 있다.

### 6.4 단일 의상과 실제 조합을 함께 검증할 수 있게 됐다

단일 의상은 특정 요구사항 준수율을 보기 좋고, 상·하의 조합은 실제 서비스
사용과 가깝다. 두 유형을 모두 유지해 원인 분석과 실사용 검증을 병행할 수 있다.

### 6.5 호출 안정성이 개선됐다

4개 모델 모두 6개 실제 Run에서 성공했다. 완전한 후보 집합이 없으면 평가를
시작하지 않는 정책 덕분에 모델마다 비교 표본 수가 달라지는 1차의 문제가 현재
2차에서는 발생하지 않았다.

## 7. 아쉬운 점과 현재 한계

### 7.1 여섯 조합을 모두 평가하지 못했다

현재 실제 평가 범위는 균형 잡힌 6개 조합이 아니다.

- D1 · 여성 크롭 티 + 부츠컷: 실제 평가 없음
- D2 · 여성 슬림 폴로 + 파라슈트: 실제 평가 2회
- D3 · 여성 그래픽 크롭 티 + 와이드 슬랙스: 실제 평가 1회
- E1 · 남성 로고 티 + 와이드 데님: 실제 평가 1회
- E2 · 남성 그래픽 티 + 파라슈트: 실제 평가 없음
- E3 · 남성 체크 셔츠 + 와이드 슬랙스: 평가 1회, 새 실제 Run 1개는 미평가

D2가 중복되어 현재 순위에 두 번 반영됐고 D1·E2는 실제 표본이 없다. 따라서
현재의 `case_count=5`는 서로 다른 다섯 케이스가 아니라 평가된 Run 다섯 개라는
의미다.

### 7.2 평가자 구성이 Run마다 다르다

수경과 한승민은 평가된 다섯 Run을 모두 완료했지만, 다른 평가자는 일부 Run에만
참여했다.

| 평가자 | 완료 Run | 저장된 표 |
| --- | ---: | ---: |
| 수경 | 5개 | 30표 |
| 한승민 | 5개 | 30표 |
| 이정민 | 2개 | 12표 |
| 보경 | 1개 | 6표 |
| 임효민 | 1개 | 6표 |

케이스마다 평가자 집합이 달라 평가자 취향과 케이스 효과를 완전히 분리하기 어렵다.

### 7.3 대시보드의 `FINAL PICK` 표현이 이르다

2차 대시보드는 현재 1위를 `FINAL PICK`으로 표시한다. 아직 케이스가 빠져 있고
평가자 구성도 통일되지 않았으므로, 종료 조건을 충족하기 전에는 `CURRENT LEADER`
또는 `INTERIM PICK`으로 표시하는 것이 정확하다.

### 7.4 핏 규칙의 임계값을 검증해야 한다

`relative-fit-v1`은 결정론적이라 재현성은 좋지만, 현재 임계값은 파일럿 규칙이다.
예를 들어 하의 전체 핏을 허리와 힙 중 더 타이트한 영역으로 결정하고, 총장 비율로
발목·풀렝스·롱을 구분한다. 실제 의류 데이터와 사용자 체감에 맞는지 별도 검증이
필요하다.

### 7.5 레퍼런스 오염 방지 효과를 수치로 분리하지 못했다

프롬프트 구조는 개선됐지만 현재 집계는 전체 선호와 품질 점수만 보여준다.
착용컷의 얼굴 복제, 체형 대체, 다른 의상 혼입이 실제로 얼마나 감소했는지
전용 지표나 실패 태그가 없다.

### 7.6 비용 기록은 아직 불완전하다

FLUX.2 Max만 회당 $0.16이 기록됐고 나머지는 모두 0으로 남아 있다. 최종 모델
선정에서 비용을 사용하려면 동일한 기준으로 실제 비용을 기록해야 한다.

## 8. 현재 판단

### Nano Banana 2

- 현재 종합점수, 선호도, 품질 네 항목 모두 1위다.
- 평균 응답시간 22.5초로 품질 대비 속도도 가장 균형이 좋다.
- 남은 케이스에서도 같은 우위를 유지하면 최종 후보로 가장 유력하다.

### GPT Image 2

- 두 개의 남성 조합 Run에서 1위를 기록했다.
- 의류 보존은 강하지만 체형 보존과 전체 선호도에서 Nano Banana 2보다 낮다.
- 여성 조합과 인물 오염 케이스에서 체형 유지 여부를 추가 확인해야 한다.

### Nano Banana 2 Lite

- 속도는 가장 빠르지만 현재 품질과 선호도 격차가 크다.
- 1차에서는 균형 잡힌 2위였으므로, 프롬프트 v2 또는 상·하의 동시 입력과의
  궁합 문제인지 케이스별 결과를 확인할 필요가 있다.

### FLUX.2 Max

- 1차와 마찬가지로 가장 느리고 기록 비용이 가장 높다.
- 현재 순위와 품질로는 운영 비용을 정당화하기 어렵다.
- 남은 평가에서 뚜렷한 반전이 없다면 최종 후보 우선순위가 가장 낮다.

## 10. 최종 회고

이번 2차 변경의 핵심은 모델 수를 줄인 것이 아니라 입력의 의미를 명확히 만든
것이다. 사용자는 MVP 수준의 정보만 입력하고, 서버는 선택 사이즈 실측과 아바타
기준 치수로 핏을 계산한다. 인물과 의상 레퍼런스의 권한도 분리해 1차에서 확인된
착용컷 인물 오염 문제를 구조적으로 다뤘다.

현재 데이터에서는 `Nano Banana 2`가 품질과 속도 모두 가장 좋은 선택으로
나타난다. 그러나 같은 D2 케이스가 두 번 포함됐고 D1·E2가 빠져 있어 “최종 모델이
결정됐다”고 말하기에는 이르다.

현재 결론은 다음과 같다.

> 2차 입력·프롬프트·집계 구조는 준비됐고 Nano Banana 2가 강한 선두 신호를
> 보였다. 남은 조합을 같은 평가자 조건으로 채운 뒤 최종 모델을 결정한다.
